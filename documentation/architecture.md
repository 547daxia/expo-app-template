# Architecture

## Runtime stack

- Expo SDK 56, React Native 0.85, and React 19
- Expo Router with Continuous Native Generation (CNG)
- TypeScript with strict checking and `@/` absolute imports
- Gluestack UI with Uniwind and Tailwind CSS for shared components and styling
- Gluestack SVG icons for shared controls, `@expo/vector-icons` for navigator
  icons, and `react-native-svg` for custom artwork
- TanStack Query + Axios + React Query Kit for server state
- TanStack Form + Zod for forms and validation
- Zustand for global client state
- Expo SecureStore for native credentials and MMKV for non-sensitive local state

## Repository boundaries

| Path | Responsibility |
| --- | --- |
| `src/app/` | Expo Router layouts and thin route re-exports |
| `src/features/` | Feature-owned screens, components, API hooks, and state |
| `src/components/ui/` | Replaceable Gluestack-generated primitives and provider code |
| `src/components/` | Shared project-owned wrappers and compound components |
| `src/lib/` | API infrastructure, storage, navigation, auth utilities, and global hooks |
| `modules/` | Project-local Expo native modules and their TypeScript facades |
| `assets/` | App icon, splash, adaptive icon, and web favicon |
| `documentation/` | Plain Markdown operational documentation |
| `docs/` | Astro/Starlight documentation website |

## Feature conventions

Feature directories use kebab-case names. Screens use the `*-screen.tsx` suffix.
Feature-only components live under that feature's `components/` directory.
Reusable project wrappers and compound components live under `src/components/`
and may compose primitives from `src/components/ui/`. The generated layer must
not import project-owned components and must not contain project tests or
helpers. A feature may import an unmodified generated primitive directly. There
is no shared UI barrel or legacy compatibility directory; import each component
group directly.

Feature routes should remain small:

```tsx
export { FeedScreen as default } from '@/features/feed/feed-screen';
```

Use direct imports instead of feature barrel exports. Relative imports are appropriate inside one feature; cross-feature and shared imports use the `@/` alias.

## Root composition

[`src/app/_layout.tsx`](../src/app/_layout.tsx) composes the runtime providers in this order: gesture handling, Gluestack UI, keyboard handling, navigation theme, React Query, bottom-sheet modals, and flash messages. It also hydrates authentication, restores the selected theme, controls the splash screen, and provides a recoverable application error boundary. Authentication hydration is asynchronous; the route tree is not mounted until it resolves, and storage errors fail closed to signed-out state.

The authenticated area is defined by [`src/app/(app)/_layout.tsx`](../src/app/%28app%29/_layout.tsx). It redirects first-time users to onboarding, signed-out users to login, and otherwise renders the Feed, Style, and Settings tabs.

## Included application surfaces

- Onboarding records first-use completion and routes to login.
- Login validates a demo form and signs in only outside production.
- Feed supports loading, empty, error, refresh, detail, and create-post flows.
- Style is the interactive catalog for installed generated groups and important
  reusable project components.
- Settings controls the persisted theme, displays app metadata, optionally
  links to `EXPO_PUBLIC_APP_URL`, and signs the user out.

## Native modules and generation

The repository uses CNG. Native projects generated by `expo prebuild` are local
build artifacts and must not be committed. Project-local Expo Modules live in
`modules/` and are discovered through `expo-module.config.json`. Native project
configuration belongs in `app.config.ts` or an idempotent Expo config plugin,
not in committed generated projects. See [Local Native Modules](./native-modules.md).
