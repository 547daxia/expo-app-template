Complete this checklist before creating a development build, enabling EAS Update, or publishing the repository. The template contains example identifiers from its original source; do not ship with them unchanged.

## 1. Create local configuration

Copy the committed example and set the development API endpoint:

```bash
cp .env.example .env
```

`.env` is ignored by Git. Values prefixed with `EXPO_PUBLIC_` are included in the application bundle, so they must never contain secrets. See [Environment Variables and Configuration](/getting-started/environment-vars-config/) for the complete behavior.

## 2. Replace application identifiers

Update the constants in `env.ts` for all three environments:

- `NAME`
- `BUNDLE_IDS`
- `PACKAGES`
- `SCHEMES`

Use bundle identifiers and Android package names that your team owns, for example `com.example.myapp`, `com.example.myapp.preview`, and `com.example.myapp.development`. The production identifier cannot be changed after an app has been released to a store.

Then update `app.config.ts`:

- `EXPO_ACCOUNT_OWNER`: your Expo account or organization slug.
- `slug`: a unique Expo project slug under that account.
- `description`, icons, splash screen, and Android adaptive-icon color as needed.

Verify the resolved configuration before building:

```bash
pnpm exec expo config --type public
```

Check that `owner`, `slug`, `scheme`, `ios.bundleIdentifier`, and `android.package` show your values for the selected `EXPO_PUBLIC_APP_ENV`.

## 3. Create and link your EAS project

The template's `app.config.ts` contains an EAS project ID from its original source. Replace it before using EAS Build or EAS Update.

1. Sign in to the Expo account that will own the app:

   ```bash
   pnpm dlx eas-cli@latest login
   ```

2. Create or link an EAS project, explicitly replacing the template's existing link:

   ```bash
   pnpm dlx eas-cli@latest init --force
   ```

3. Confirm that `EAS_PROJECT_ID` in `app.config.ts` now contains the project ID returned by EAS. If the CLI cannot update this dynamic config file automatically, copy the returned ID into that constant yourself. Do not retain the template's original ID.

4. Confirm that the resolved configuration contains your new ID:

   ```bash
   pnpm exec expo config --type public
   ```

   The value must appear at `extra.eas.projectId`.

`projectId` is not a secret, but it identifies the EAS project that receives builds and updates. Keep it consistent across the repository, `eas.json`, and your CI environment.

## 4. Initialize Git and publish when ready

For a new checkout without Git history:

```bash
git init -b main
git add .
git commit -m "chore: initialize project"
```

After creating an empty repository with your Git host, add the remote and publish the branch:

```bash
git remote add origin <your-repository-url>
git push -u origin main
```

Before the first push, update the `repository.url` field in `package.json`; it still points to the source template by default.

## 5. Validate ownership and create a development build

Run the local checks:

```bash
pnpm check-all
pnpm doctor
```

Then create a development build under your EAS account:

```bash
pnpm build:development:ios
pnpm build:development:android
```

This project uses Continuous Native Generation. Do not commit generated `ios/` or `android/` directories; configure native behavior through `app.config.ts` and Expo config plugins.
